## 第八轮：分支页签新增「合并到当前分支」

用户需求：在「分支」页签加一个分支合并入口（截图圈了工具栏与本地分支行）。

### 实现
- **引擎** `GitEngine.merge_branch(path, source, *, no_ff=False, message=None, author, email)`
  - `source` 支持 `feature/x`（本地）、`origin/main`（远程跟踪）、`refs/...`（完整引用）；
    新增模块级 `_resolve_merge_source()` 统一解析，**本地同名分支优先于远程**
  - 语义对齐 git：`merge_base` 判定 → base==source → `already_merged`；
    base==local 且非 no_ff → `fast_forward`（更新 ref + `reset --hard`）；
    否则 `porcelain.merge(..., no_ff=True, message, author, committer)` 生成双父提交
  - 冲突处理复用 `pull()` 那套：先 `merge_tree()` 只读预检（不动工作区/索引），
    有冲突直接抛错；真合并抛异常或返回冲突时 `_abort_merge(repo, before_head)` 回滚
  - 三个前置拦截：游离 HEAD、`.git/MERGE_HEAD` 存在（上次合并未完成）、工作区有未提交改动
  - `porcelain.merge` 的 author/committer 要传 bytes，格式 `b"Name <email>"`
- **UI** `repos.py`
  - 工具栏「切换到选中分支」后加 `btn_branch_merge`（primary），并入 `_set_busy` 禁用列表
  - `_selected_branch_name()`：按**焦点**决定优先读本地表还是远程表（否则会误用另一张表的残留 currentRow）
  - `_merge_selected_branch()`：未选中 → 提示；选中的就是当前分支 → 提示无需合并；
    confirm 里写明「能快进则快进 / 否则建合并提交 / 冲突自动回滚」
  - `_on_merge_done(result)`：按 `result` 给四种文案（快进/合并提交/已包含/同一提交），
    完成后 `refresh_all()`（状态、分支列表、提交演化图一起更新）

### 结果
- 引擎 8 个场景实测：快进（advanced=2）、真合并（双父）、已包含、冲突（HEAD/文件/MERGE_HEAD 均不变）、
  远程分支、脏工作区拦截、不存在分支、自合并
- `tests/feature_test.py` 新增 `test_merge_branch()` **22 项** → feature **321 / 0**
- 自检新增 4 项（快进、工作区同步、冲突拦截、冲突后文件不变）→ **114 / 0**
- 其它回归：smoke 47 / ui 25 / publish 54
- 版本 1.2.1

### 注意
- 快进是默认行为（与 git 一致），不会产生合并提交；需要保留合并点时可传 `no_ff=True`（UI 暂未开放开关）
- 远程分支要先「拉取远程分支」才能在本地合并（合并的是 `refs/remotes/...` 的本地快照，不联网）

## 第九轮：合并冲突解决窗口

用户需求：冲突时不要只弹「已阻止合并」的错误框，要能**在窗口里手动编辑解决**。

### 引擎（gitengine.py）
- `start_merge(path, source)`：**不预检阻止**，让 dulwich 真正写冲突现场
  （工作区带 `<<<<<<< ours / ======= / >>>>>>> theirs`、索引存冲突、留下 MERGE_HEAD），
  返回 `result="conflicts"` + 文件列表；`merge_branch()` 保留为「有冲突就回滚」的保守路径。
- `merge_state(path)`：读现场（active/branch/source/message/冲突清单/binary 判定）。
- `conflict_text(path, name)`：取 base/ours/theirs 三方内容 + 工作区当前内容。
- `resolve_conflict(path, name, content)`：写文件 + `porcelain.add`（清冲突标记）。
- `finish_merge(path, message, author, email)`：`index.commit(store)` 生成 tree，
  自己构造双父 `Commit`，更新 HEAD，删 MERGE_HEAD/MERGE_MSG。
- `abort_merge(path)`：`_abort_merge()` + 清理 MERGE_HEAD/MERGE_MSG。

### UI（ui/merge_dialog.py，新增）
左侧冲突文件列表（●/✓）+ 右侧编辑器 + 三个快捷按钮（用我的/用对方的/还原标记）
+ 保存并标记 + 完成合并 + 中止合并；关窗保留现场，下次点合并按钮自动重开。

### 四个真坑（都实测踩到）
1. **冲突索引不是 stage 1/2/3**：dulwich 1.2.x 用 `ConflictedIndexEntry`（ancestor/this/other）
   放在单个 `(path, 0)` 条目里；`Index.items()` 的键还可能是裸 `bytes` 而不是元组 →
   取值要 `entries.get((p, 0), entries.get(p))` 两种都试。
2. **`porcelain.merge` 前必须 `reset --hard`**：dulwich 的 `update_working_tree` 比对索引 stat，
   索引不新鲜（用 git CLI 操作过）时会把干净工作区误判成「有本地改动」，抛
   `WorkingTreeModifiedError`。
3. **手动构造 Commit 的时间戳必须是 int**：float（`time.time()`）会写出
   `1792257058.1184402` 这种畸形值，后续任何 git 读取都报 `ObjectFormatException`。
4. **`QTextEdit.ExtraSelection` 必须选中整行**：`QTextCursor(block)` 是零宽选区，
   背景色完全不渲染（截图里一个高亮像素都没有）；要 `cursor.select(LineUnderCursor)`。
另：`_abort_merge` 原先不清理「合并带进来、HEAD 没有」的文件 → 中止后残留未跟踪文件
（`status().clean` 为 False），现按目标 tree 的路径集合删除。

### 顺手修的既有 flaky（publish_test）
「概览提供发布入口」偶发失败：`MainWindow` 切页会 reload 远程仓库列表，假令牌 401 →
`_on_error` 弹**模态框**，把 `processEvents` 循环卡死。修法：测试里打桩
`ExplorePage.reload = lambda self: None`，并把等待条件改成「任务空闲且按钮可用」。

### 结果
- feature **348 / 0**（+27：冲突流程 23 + 高亮断言 4）
- 自检 **118 / 0**（+4：进入现场/写入标记/清单/完成合并）
- 其它：smoke 47、ui 25、publish 54（连跑 3 次稳定）
- 版本 1.2.2；截图 `build/preview-conflict2.png`

## 第十一轮：删除分支支持删除远程分支（v1.3.0）

用户需求：截图里选中 `origin/分支图` 后点「删除分支」只提示「请先选择要删除的分支」，
要求既然能删本地分支，也要能删**远程仓库上的分支**。

### 引擎（`gitdesk/core/gitengine.py`）
- `split_remote_ref(path, tracking)` → `("origin", "feature/x")`；**远程名按长度倒序匹配**，
  避免 `ori` 抢走 `origin/...`（`D:\Git\git\...` 这类多斜杠远程名也安全）
- `remote_default_branch(path, remote, ...)`：用 `porcelain.ls_remote(url, username=, password=)`
  返回的 **`LsRemoteResult.symrefs[b"HEAD"]`** 拿默认分支（本机没 fetch 过 `refs/remotes/<r>/HEAD` 时靠它兜底；
  失败返回空串，不阻断删除）
- `delete_remote_branch(path, tracking, credential, platform, progress, detail, cancel)`：
  - 真正删除靠 `porcelain.push(repo, remote, b"refs/heads/<branch>", delete=True)`
    → 内部 `_select_push_refs(delete=True)` 把 `(None, ref, force)` 转成 `new_refs[ref] = ZERO_SHA`
  - 三道拦截：远程跟踪引用不存在（提示先刷新）/ 本地 `refs/remotes/<r>/HEAD` 命中 / 远程 symref 命中
  - 成功后删掉本地 `refs/remotes/<remote>/<branch>`，列表立刻少一行
  - 远程拒绝（reject/error）原样转达
- **坑**：`porcelain` 在 dulwich 1.2.17 是**包**（`dulwich/porcelain/__init__.py`），不是单文件 py

### 界面（`repos.py`）
- `_selected_branch()` → `(kind, name)`；`kind` 来自新增的 `self._branch_source`
  （在两张表的 `itemSelectionChanged` 里、且 `hasFocus()` 时记录）
  **不能只看 `hasFocus()`**：点「删除分支」时焦点已经在按钮上，会误判成另一张表
- `_delete_branch()` 按 kind 分派；远程走 `_delete_remote_branch()`：
  确认弹窗（写明远程名 + 不可恢复）→ 令牌校验 → `tasks.run` 带进度/可中止 → `_on_remote_branch_deleted()` 通知 + `refresh_all()`
- 远程分支区上方加一行提示「选中远程分支后点『删除分支』，会直接删除远程仓库上的该分支」
